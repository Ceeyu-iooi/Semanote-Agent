# JavaScript 智能体设计

活动实现位于 agent/，Node.js 24 原生 ESM；Java/Spring Boot 负责 Web 与持久化，通过 NDJSON 管道调用本地智能体。旧 P03 Python 实现和当时测试见 [P03 历史记录](p03-report.md) 与0.1.1标签，当前不保留双实现。

## 调度与可信边界

1. contract.js 校验请求身份、十一类任务、文本容量及 Unicode；仅选词性时补充分词依赖。
2. agent.js 在原文边界无损分块（最多650码点），为缺失成功缓存的任务构造联合推理，paragraphs 本地执行。
3. provider.js 仅访问明确选择的公开HTTPS供应商，限制响应大小与超时；不自动重试、跟随重定向或切换供应商。固定系统提示前缀有利于供应商缓存，但实际命中只按usage记录。
4. grounding.js 对齐原文、标点及空白，contract.js 生成可信码点区间；情感/意图/语义检查完整覆盖，关系角色检查原文依据。
5. 合并各块结果，关键词按跨块排名汇总；词性与最终分词逐项关联，事件和关系保留证据；每层独立成功/失败及尝试身份。
6. Web 只接收候选。用户显式保存后 Java 事务生成不可变快照，统计与导出绑定该快照；人工结果不被自动替换。

## 性能与成本

- 联合请求将同块多任务的重复原文及提示开销合并，避免每层单独请求；具体token与耗时以实际回执为准。
- 缓存成功层隔离供应商/端点/凭据摘要/模型/参数/提示词/文本，损坏内容视为未命中。新提示词自然隔离旧缓存，保留旧付费缓存文件。
- 词性显式重试携带已成功分词，拒绝重分词；保留其他成功层，减少重复推理。长文跨块的远距离关系仍是能力边界。
- 核心位置查找使用原生indexOf定位，再转换码点；有序覆盖用线性字节数组检查。原文最多10000码点，模型任务/条目数和输出均有界。
- 缺少usage或缓存usage时保持null和未知标志；不把请求次数、token或缓存比例推断成货币账单。

## 与工作区协作

onProgress 报告真实已处理块和逐层检查结果。前端中央正文保留原文，抽取卡片仅在真实结果返回时播放呈现动画，结果数、统计和详情来自同一展示来源；减少动效不影响结果。候选、人工草稿、历史原文和保存快照明确区分。编辑原文隐藏旧标注，避免过期区间误示。

## 验证

单元检查覆盖无损/emoji/CRLF、实体语境、完整覆盖、缓存损坏、成功层重试与依赖；独立CLI、CSV工具及HTTP持久化回归单独验证。十组原创样本实际调用百炼，保留失败和修复回执；回放不计真实请求。无人工金标准不报告准确率/F1。参见 [运行和验证方法](agent-usage.md)。
