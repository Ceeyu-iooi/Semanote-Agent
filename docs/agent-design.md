# 文本标注智能体设计

阶段：P03；日期：2026-10-27；状态：独立模块已实现并验证，待用户验收；P04/P05 未开始。

## 1. 目标与已确认方案

Python 3.12 独立模块与命令行，使用标准库，无第三方运行依赖。首选 DeepSeek 官方端点、`deepseek-flash`、非思考 JSON 模式，默认 HTTPS I/O 超时 60 秒、输出上限 8192 tokens，不自动重试或换供应商。用户在本聊天确认技术、完整标注规则包和输入输出契约，见[决策清单](decisions.md)。

分词、关键词、词性、实体均已实现，可分别或组合调用。[标注契约](annotation-contract.md) `1.0.0` 固定 Unicode 码点区间、UD 17 类词性、抽取式关键词与五类实体。项目发布版本仍为 `0.1.0-docs.1`，模块格式版本不等于项目发布。

## 2. 调用链和职责

`AnnotationAgent.annotate` → 输入校验与任务计划 → 逐层 `ChatCompletionsProvider.generate` → 提示构造与 HTTPS 请求 → 严格 JSON 解析 → `convertItems` → 逐层结果与错误汇总。

- `rules` 固定任务/标签/版本及精确文本摘要；`config` 只读本地配置，不执行 shell 展开。
- `prompts` 将原文作为 JSON 数据传递，嵌入的命令不能获得工具或配置权限。
- `providers` 隔离 HTTPS 协议；禁用重定向，防止认证头被转发；错误不返回供应商正文或凭据。响应传输保护上限为 8 MiB，不是产品文本长度限制。
- `annotations` 从词面、序号和已有词项建立可信位置，验证覆盖、顺序、标签、重复和依赖。区间校验不证明语言学判断必然正确。
- `agent` 固定执行顺序并隔离预期失败，生成自动候选；`__main__` 处理 JSON 输入、退出码和禁止覆盖的输出。

执行按分词、关键词、词性、实体的固定次序串行进行。POS 单独选择时显式补执行分词；分词失败仅阻断 POS，关键词/实体继续。一份四类组合通常发出四次模型请求；分词失败时 POS 不发请求。串行不代表每次都耗时相同，不给出未经测量的整体时延承诺。

这是有界任务编排智能体：任务与依赖由冻结规则决定，模型负责语言标注候选，不随意删减用户任务、调用系统工具或写数据库。

## 3. 供应商扩展与恢复

`ChatCompletionsProvider` 支持 DeepSeek 和通过独立环境前缀配置的兼容供应商；端点、模型、密钥、JSON 能力与额外参数分别配置。其他供应商的 `thinking` 等参数须显式提供，不继承 DeepSeek 专有参数；保留字段不能被额外参数覆盖。协议不同的供应商通过实现 `providerName`、`modelName`、`generate(taskType, text, tokens)` 并返回 `ProviderReply` 的新适配器接入。

无自动故障转移；一次调用只使用所选供应商。`retryFailed` 先检查同请求、同修订、同原文摘要和完整成功层，再仅重试失败层，追加尝试并保留成功层。程序不修改输入、旧响应或人工版；输出结果仍是自动候选。

P03 是无状态模块：不提供持久化、跨进程幂等注册、历史查询、Web 异步任务状态或批次恢复。P04 需把本契约映射到任务、尝试、结果和快照，并实现这些职责；CLI 输出不是产品的正式导出快照。

## 5. 验证边界

28 项本地测试覆盖 Unicode、重复/重叠、依赖、恢复、模型空/坏响应、供应商隔离、诊断脱敏及 CLI。普通与 `python -O` 均通过。真实 DeepSeek 合成文本调用完成四类能力、五类实体及合法空结果；首轮分词出现空白词项被拒绝，显式重试恢复成功。详情见 [P03 记录](p03-report.md)。

其他供应商只有适配/协议测试，未使用真实凭据远程验收。TBD[D09] 仍未授予真实语料外发许可；TBD[D10] 未形成经人工复核的金标准，不报告准确率、F1 或达标阈值。
