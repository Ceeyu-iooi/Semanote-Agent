# 课程提交与验收清单

来源：课程 PDF 第 14–22 页及两份本地 Word 模板。这里定义交付规则，不代表任何业务成果或正式报告已经完成。日期、成员、班级、学号和名单顺序依 TBD[D05]、TBD[D12] 填写。

## 中期（小组，电子版）

- [ ] 系统原型：`日期_小组名单_系统原型设计.rp` 或 `.pdf`，覆盖主要界面和流程；交互流程浏览器不是产品原型的替代品。
- [ ] 中期报告：`日期_小组名单_中期报告.docx`，不少于 1,500 字，沿用原始模板格式。
- [ ] 内容包括项目/师生信息、背景、需求、方案论证、功能/技术架构、原型、任务分工、进度、参考文献。
- [ ] 同批文件名及正文中的名单顺序固定；不得照搬模板示例日期和成员。
- [ ] 第 12 周周五 17:00 截止，具体公历日期确认后登记。

## 集中验收（提前一天 17:00 提交）

| 材料 | 规范文件名 | 核查条件 |
|---|---|---|
| 小组汇报 | 日期_小组名单_验收汇报稿.pptx | 实际分工与工作量占比，包含组织协调贡献，占比合计 100% |
| 小组源码 | 日期_小组名单_软件源代码.zip | 整套源码、锁文件、许可证、配置示例、启动和恢复说明；不含密钥、缓存与无关测试文件 |
| 小组数据库 | 日期_小组名单_软件数据库.zip | 与源码版本配套；含结构和数据的适用备份，且实际验证恢复 |
| 小组说明书 | 日期_小组名单_软件操作说明书.docx | 概述、环境、配置、启动、操作流程、主要界面截图、FAQ 与注意事项 |
| 每人报告 | 日期_学号_姓名_课程设计报告.docx | ≥5,000 字（不含源码），电子版和纸质版，每人单独撰写 |

MySQL 提供压缩后的 SQL 备份；其他数据库用其适用方法备份，并在报告说明。若仅使用本地文件存储，可不交数据库备份，但须在报告说明，并核查文件恢复流程，不能一律假定必须用 MySQL。

## 个人报告

- [ ] 遵循本地个人报告模板，讲清整体框架及本人工作定位，再展开本人负责内容；不互相复制整体描述。
- [ ] 包括背景、技术、任务要求、需求、功能/技术框架、开发环境、数据结构、模块设计、实现结果、总结建议、参考文献和附录。
- [ ] 模块内部层次、关联和接口说明与源码一致；功能流程细化到实际函数接口。
- [ ] 图表、界面截图、测试指标和工作量均来自真实已完成成果，参考文献实际核实。
- [ ] 报告字数排除源代码；纸质版内容与最终电子版一致。

## 现场验收

- [ ] PPT 汇报、软件演示、源码及操作说明书展示、技术问答，全体成员协作。
- [ ] 集中验收为正规考试；缺席原则上视为放弃。特殊情况请假及成绩认定条件依 PDF 第 15 页与老师确认，不自行承诺结果。
- [ ] 四类核心任务、人工校对、导出、批量及异常场景按实际完成情况演示；不能只展示静态截图。
- [ ] 在目标环境验证配置、启动、数据恢复和主要流程；外部能力不可用时按已确认方案清楚呈现真实状态。
- [ ] 现场验收占 60%，个人报告占 40%；优秀需基本要求及部分选做且完成质量较高，不承诺成绩。
- [ ] 最终时间地点以老师通知为准，第 18 周安排不自行换算成确定日历时间。

正式课程材料与含真实语料的备份保存在本地 deliverables，通过课程指定渠道由用户提交。不要自动向老师发送邮件、微信或上传公开仓库。
