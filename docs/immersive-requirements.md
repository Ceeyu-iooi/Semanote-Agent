# 沉浸式工作台重构需求

日期：2026-10-29。来源：本聊天用户的工作台草图、供应商设置截图及后续技术栈、README、PR 命名指令。本次为功能分支改造，不自动发布下一版本。

## 可验证表述

1. 主界面及独立开发者中心取消侧边导航，以顶部导航切换主要页面；窄屏可浏览全部入口，当前页面状态明确。
2. 标注页进入三栏沉浸式工作区：中央原文及编辑工具为视觉中心，两侧卡片展示来自该文本的十一层标注；正文下方保留逐篇交互图表、关系/事件与时间线。卡片和图表均能回到同一原文证据，人工修订、历史与保存快照范围不变。
3. AI 标注的卡片呈现真实返回结果，以从正文方向进入的交错淡入/轻微回弹表达“抽取”；加载、失败、成功零条目和缓存复用区分。动效不伪造推理进度，减少动态效果偏好生效。
4. 设置使用侧边导航；模型管理参照截图的供应商列表＋所选供应商详情布局，使用真实配置状态，不虚构连接成功、余额或同步。保留自定义供应商和安全密钥编辑能力。
5. Git 实际父关系保留横向布局，分支/轨道颜色有文字图例，卡片与关系线一致；时间选择同时作用于图上的位置/已走区间。文件变更以结构化文件列表呈现，代码差异有文件、行号和新增/删除标识。
6. 系统 Archify 的对应节点可以进入智能体、前端、后端、数据库框架；导航具有层级和返回入口，并使用简短的放大/切换过渡。不能用示意图冒充实际 Git 历史。
7. 技术栈为 Vue＋JavaScript＋Bootstrap、Java/Spring Boot、JavaScript 智能体。盘点所有被 Git 跟踪的 Python，迁移维护、构建、启动、验证与示例工具到 Node.js；退役历史 Python 智能体及其专属测试，必要异常与契约能力迁移到 JavaScript 测试。历史实现仍可从 0.1.1 标签恢复；不删除用户 profile 或外部工具的 Python 文件。
8. 遍历活动智能体的输入、分块、缓存、供应商、定位、恢复及十一层显示链路，修复有证据的缺陷。远程检查沿用百炼，仅使用原创合成文本；不扩大真实语料授权，不把结构通过称为语义准确率。
9. README 至少实际参考 20 个公开项目，记录来源与格式蒸馏，重建项目原生的阅读顺序和真实截图；安装命令与当前无 Python 运行链路一致。
10. 至少完成十轮有目标、有证据、有修正或结论的迭代，覆盖桌面/窄屏、十一层、编辑与保存、图表、设置、Git、架构、异常和运行恢复。最终记录实际通过、剩余边界及开发依赖恢复方法。

## Git 命名

小提交继续使用 `feat：中文内容` / `fix：中文内容`。新 PR 标题使用 `PR#实际编号：中文综合说明`，合并标题沿用 PR 标题；不改写历史提交、历史 PR 或已发布标签。功能改动在 feature/immersive-workspace，经 PR 回到 develop，未获新发布指令前不合并或打标签。
