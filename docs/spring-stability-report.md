# Spring Boot 与标注稳定性验证

本轮恢复 Java 21 与 Spring Boot 3.5 后端。继续使用既有 MySQL 表、REST 契约、8090/8081 端口和一键启停。审核、快照、来源行列和历史候选保持可读。Java 通过本地 JSON/NDJSON 调用 JavaScript 智能体。

历史失败回执包含跨句同名角色无法定位的情况。关系和事件采用原句编号，跨句角色须给出原文出现序号。意图、情感和语义可返回与本地原文片段一一对应的标签，减少逐字复述产生的定位和引号错误。返回数量、来源、覆盖和标签仍按契约校验。

相同原文与供应商配置在不同任务组合中采用一致分块。缓存按供应商、地址、凭据摘要、模型、输出参数和候选契约隔离，每层复用前重新验证。DeepSeek 首次对原创短文本返回十一层成功，重复请求和只选关系、事件、意图的请求均无新增联网调用。供应商侧缓存仍以实际回包为准。

- 16 项 Java 单元测试、63 项 Node 自动化测试与 26 项隔离 MySQL/HTTP 检查覆盖版本、候选、快照、CSV 进度与限量、15,306 份合成文本导入及 SQL 恢复。
- Edge 在桌面和窄屏验证长文件名换行、数量输入和退出确认。确认退出后验证 Spring Boot 与 MySQL 均停止。开发代理写入和发布入口启动也通过。
- 开发依赖恢复与一键启动见 [运行手册](web-usage.md)。数据集标注质量和性能仍由 D10 验收。
