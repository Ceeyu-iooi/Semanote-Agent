# Semanote-Agent 产品需求文档

阶段：P02；创建：2026-10-27；P03 回看：2026-10-28。P02 已获进入 P03 的用户指示，P03 独立模块已交付待验收，Web 后端和前端未开始。标注规则与独立模块契约以本文第 12 节和 annotation-contract.md 的已确认版本为准。

## 1. 依据、目标与用户

P01 数据库逻辑设计已交付，用户随后明确指示“执行需求文档编写”，阶段准入证据见 [验收记录](acceptance.md)。本文件依据 [课程要求映射](requirements.md)、[数据库设计](database.md)、[决策清单](decisions.md)、[课程提交清单](submission-checklist.md)、AGENTS.md、README.md 和 workflow.json 编写。课程原件仅在本地 profile 保留，本文不替代原件证据。

目标是让操作者在浏览器中管理通用中文文本，对同一份文本完成分词、关键词、词性和命名实体自动标注，检查高亮及统计，人工添加或校正结果，再保存、重读和导出 JSON；支持对选定文本批量执行。前端承载管理、交互、高亮和统计；后端负责请求校验、调用智能体、结果结构校验与持久化；智能体提供四类结构化结果，不要求从零训练模型。这里划分产品职责，不规定语言、接口路径或服务部署数量。

| 目标使用者 | 场景与目标 | 本期边界 |
|---|---|---|
| 文本标注操作者 | 输入或导入文本，核对四类结果，保存人工修订并复用成果 | 按单操作者工作流设计，不承诺账户登录、权限或任务分配 |
| 课程开发/演示小组 | 用原创合成文本演示完整闭环，核对结果、异常与恢复 | 成员和实际分工待 TBD[D05]；不在文档虚构贡献 |
| 课程验收者 | 根据固定输入、保存版本和验收条件复查行为 | 仅定义未来检查方法，不声称已有软件或实测指标 |

司法语料 train.csv 只作获授权的本地示例，不产生司法分析、裁判建议、案件分类或法律结论。真实语料外发须先满足 TBD[D09]；选择 API 路线不等于允许把真实文本发给供应商。

## 2. 范围与待决策的效力

**本期必做**：直接输入、编辑、上传、保存/重读、文本列表与来源展示；四类自动标注；结果分层与高亮；人工标注/校对；实体数量、关键词和各类标签统计；JSON 导出；批量处理和失败恢复。

**后续候选**：登录、多用户分配、协作审核、关系/事件/分类/情感等任务、语义去重、自动迁移旧区间。未获新的范围确认前不纳入验收。产品原型、课程报告和演示资料作为课程检查点管理，本阶段不生成原型或业务代码。

## 3. 页面与导航

页面名称是信息架构，不锁定前端路由、URL 或组件库。

| 页面/区域 | 可观察内容与操作 | 导航及状态 |
|---|---|---|
| 文本管理 | 文本列表、来源、当前修订、四类任务状态；新建输入、上传、选中单篇/多篇、打开工作台 | 首次为空时显示“暂无文本”和输入/上传入口；读取中有文字状态；读取失败可重试 |
| 标注工作台 | 原文、编辑/保存、任务选择、执行/重新推理、四类结果层、人工工具、保存版本选择；统计与 JSON 入口 | 顶部持续可见当前文本、修订、结果来源和是否有未保存修改；返回列表、打开历史后可回到同一文本 |
| 批次详情 | 导入或批量标注进度、总数/成功/失败/处理中/待处理、逐项来源与错误、重试入口 | 从文本管理进入，从单项打开其工作台；返回后仍能定位原批次和所选项 |
| 历史与导出区域 | 文本修订、各层自动/人工版本、已保存组合、导出清单与结果 | 可作为工作台面板，不要求额外独立页面；打开历史显示历史原文，返回当前需明确操作 |

切换文本、修订、标注层或离开页面前，如有未保存文本/人工修改，必须提示“保存/放弃/继续编辑”；失败时保留当前页内草稿。刷新/关闭浏览器后的草稿恢复是否支持待 TBD[D13]，不能承诺已持久化。导出与批量执行只能使用已保存内容；遇到草稿提示先保存或明确使用已保存版本，不能悄悄采用草稿。

窄屏应提供可访问的分区切换或滚动布局，不把同一条内容截断为无法查看；键盘能完成主流程，聚焦位置可见。任务和结果状态同时使用文字/图标说明，不只用颜色区分。支持浏览器及最小视口范围待 TBD[D08]、TBD[D10]。

## 4. 主流程与状态规则

主流程：**输入/导入 → 保存文本 → 选择任务并自动标注 → 检查分层结果 → 人工标注/校对并保存 → 查看同版统计 → JSON 导出**。保存后随时可重读；从空层开始人工标注是允许的分支；批量为对固定的一组已保存修订执行同类操作，不是新增开发主阶段。

建议语义（TBD[D13]）：

- 文本草稿与已保存文本分开；改文本形成新修订，旧修订及其结果仍可查，新修订不自动沿用旧区间。
- 自动结果明确“自动生成、未人工确认”；人工保存产生新版本并保留基线，不改原自动版；人工保存不等于金标准。
- 每个已保存组合称为快照：同一文本修订每类至多选择一个已保存结果，允许自动层和人工层组合，显示各层来源。推荐允许显式保存缺层组合，缺层标记“未包含”，不显示为零结果。
- 正式展示、统计及导出使用选中的同一已保存快照。人工编辑时另显示“草稿预览”，正式统计标为“已保存版本”，保存成功后同步更新。未保存草稿不参与导出。
- 初次自动标注成功后可直接查看并明确保存组合；已有人工组合时，重新推理成功只追加候选版，不静默替换。失败层不回退为旧成功结果并冒充本次成功。
- 同修订各层必须满足规则依赖。若 POS 依赖分词，改了分词不能继续宣称旧 POS 兼容；提示重新生成/校对 POS，或显式保存不含 POS 的组合。不能直接删除旧 POS 历史。
- 重复提交同一动作复用请求身份；显式重新推理是新动作。多个页签保存冲突时显示“已保存版本已变化”，允许重新读取/比较和重新应用修改，不能静默覆盖。

公共状态 U01：每个异步动作有开始状态与明确终态。排队/处理中显示对象和文字进度；不可重复触发同一请求；失败保留上次已保存数据，显示对象、失败环节及恢复入口。请求超时且结果未知时先查询原请求状态再重试，不能生成重复文档或重复发布。未执行、无结果、成功零条目、部分失败、完全失败分别呈现。

## 5. 功能与验收条件

以下 F01–F16 均适用 U01 和第 4 节版本语义。每项的 AC 编号用于未来实现验收，当前仅作需求完整性走查。涉及 TBD 的条件在冻结后才进行业务通过/不通过判定。

### F01 文本管理、选择与重新读取

| 项目 | 要求 |
|---|---|
| 输入、动作 | 从管理页选择已保存文本，打开工作台或重读当前记录；可查看来源与修订历史 |
| 成功 | 显示与保存时精确一致的文本、来源行列、当前修订及所选快照；列表可区分“未标注/处理中/有结果/失败”及各层状态 |
| 空内容 | 列表为空显示输入/上传入口；选中文本没有结果时显示未标注，不生成占位标注 |
| 处理中 | 列表/正文读取显示文字状态；旧数据若保留展示须标为上次读取，不冒充新选择 |
| 非法输入 | 不存在、不可用或不属于该文档的修订/快照不打开为成功页面 |
| 失败与恢复 | 读取失败可重试/返回列表；未保存草稿先按导航规则处理；不能用另一篇文本填补失败 |
| AC01 | 保存后重新打开，原文逐字符、来源坐标、修订与层选择一致；读取失败时不显示其他文本的成功内容 |

### F02 直接输入与首次保存

| 项目 | 要求 |
|---|---|
| 输入、动作 | 输入/粘贴中文及混合文本，点击保存；标题可选，不以标题代替正文 |
| 成功 | 创建可重新读取的独立文本，保留全部空格、换行、字符及输入来源；显示保存完成与当前修订 |
| 空内容 | 建议空串/仅空白拒绝创建，显示正文必填；不自动 trim 改写非空正文，最终空白定义 TBD[D06] |
| 处理中 | 显示保存中，同一请求的重复点击不多建文本 |
| 非法输入 | 超过确认长度等校验错误指出位置/限制与实际值；不截断后静默保存 |
| 失败与恢复 | 保存失败保留本页输入及明确未保存状态；可修正或在查询原请求状态后重试 |
| AC02 | 对包含换行、首尾空格、英文、数字和 emoji 的原创输入保存重读，正文精确一致；空/超限按确认规则拒绝，重复提交只创建一次 |

### F03 上传、解析与导入

| 项目 | 要求 |
|---|---|
| 输入、动作 | 选择本地文本文件，确认文件、解析规则及导入；train.csv 使用 UTF-8 BOM 三列分别取文本；TXT 为 TBD[D06] 的格式候选 |
| 成功 | 显示导入总数、成功/失败项与来源定位；CSV 每个单元格独立成为文本，重复出现全部保留，不把列名当标签；建议 TXT 单文件单文本，不自动按行切分 |
| 空内容 | 未选文件时提示选择；零字节、仅表头、空单元分别给出可定位结果；空单元不生成可推理的空文本，处理策略待 TBD[D06] |
| 处理中 | 区分上传中与解析/保存中；显示真实进度或“处理中”，无可靠总数时不编百分比；明确是否已有成功项落盘 |
| 非法输入 | 格式/编码不支持、CSV 行宽或引号损坏、大小超限时说明原因与位置；不能乱码替换、截断或默认拼接三列；整文件无法可靠定位时不假装逐项导入成功 |
| 失败与恢复 | 文件级失败可重新选择/修正后导入；可定位单项失败按已确认逐项策略保留成功项；网络重传复用同批次，明确再次导入创建新批次 |
| AC03 | 本地审计数据完整成功导入保留 15,306 次出现和行列关系、1,607 个精确内容组；公开验收用原创重复三列 CSV 检查同语义；原件摘要不变，无真实文本外发 |

### F04 编辑文本、保存新修订

| 项目 | 要求 |
|---|---|
| 输入、动作 | 对已保存文本进入编辑，修改正文并保存；未改变内容时建议显示“无文本变更”，不新增正文修订，元数据变更另处理 |
| 成功 | 保存新修订并保留原始内容和父链；返回当前原文，新修订显示尚无适配标注；历史入口仍可看旧原文/结果 |
| 空内容 | 清空正文按 TBD[D06] 拒绝保存，不删除原记录或旧结果 |
| 处理中 | 保存时显示目标文本和保存中；旧推理仍绑定它启动时的旧修订 |
| 非法输入 | 超限、陈旧保存基线或不匹配修订被拒绝；不自动迁移区间 |
| 失败与恢复 | 保留编辑草稿及原已保存版；版本冲突提示重新读取/比较后重新应用；可放弃草稿返回已保存版 |
| AC04 | 修改一个字符后，新修订不显示旧区间为当前结果；历史文本/人工版不变；失败及陈旧页签不能覆盖已保存版 |

### F05 四类任务选择与自动标注

| 项目 | 要求 |
|---|---|
| 输入、动作 | 在确定的已保存修订上选择单类或组合执行；四类能力均必须提供；未保存文本需先保存或明确使用已保存版 |
| 成功 | 每个所选层显示独立成功/失败、规则版本与自动来源；结构/区间验证通过才可作为成功候选；明确保存选中的组合后可重读 |
| 空内容 | 无文本/无选中任务不提交；成功且零条目显示“该层未发现结果”，不能与失败混同 |
| 处理中 | 按层显示待处理/处理中；不虚构进度；同次请求不可重复创建；文本在处理中修改不会改变任务输入 |
| 非法输入 | 任务/规则不支持或缺少必要依赖时说明并禁止产生伪成功；POS 所需分词依赖显式补执行，并在 effectiveTasks 和结果中标明 |
| 失败与恢复 | 工具、授权、网络、结构校验失败按层说明；保留旧已保存版和本次成功层，允许重试失败层或重新选择组合 |
| AC05 | 四类可分别/组合发起；故障注入一层失败时其余层状态真实，失败层不返回空数组冒充成功；旧修订任务完成不覆盖当前修订 |

### F06 分词层

| 项目 | 要求 |
|---|---|
| 输入、动作 | 对指定修订执行分词，打开分词层检查词序和边界；已确认词语粒度、标点单列、非空白完整覆盖且不改原文 |
| 成功 | 按原文顺序展示词项，选中词项能定位对应原文区间；保留原文，不把分隔后的展示串写回正文 |
| 空内容 | 空输入按 F05 阻止；合法零词项必须满足已确认规则，正文有可分词内容但返回空且违反规则应判失败 |
| 处理中 | 分词层标为处理中，旧版可查看但标明旧版；不占用其他层作为替代 |
| 非法输入 | 越界、错误切片、词序错误、规则禁止的缺失/重叠项不能进入已校验结果 |
| 失败与恢复 | 展示分词失败原因，允许重试或按规则人工补充/拆分/合并；保留旧分词版本和依赖关系 |
| AC06 | 每个词项可按冻结的区间规则反查原文；用重复词、emoji、换行样例校验边界，不允许全部同词都定位到第一次出现 |

### F07 关键词层

| 项目 | 要求 |
|---|---|
| 输入、动作 | 执行关键词提取，查看词条、顺序/分数（工具确有提供时）及定义允许的原文位置；已确认最多 10 个抽取式原文词条及所有精确出现区间，不生成模型分数 |
| 成功 | 显示词条及自动/人工来源；有原文位置时可逐处定位，无位置的文档级词条显示为列表并明确“无原文定位”，不伪造高亮 |
| 空内容 | 合法无关键词显示零条目；未执行/失败不能显示为零条目成功 |
| 处理中 | 显示关键词层处理中；其他已保存层与其统计保持版本标识 |
| 非法输入 | 词条/分数或位置不符合冻结规则时拒绝作为成功结果；不能用首次字符串匹配补齐所有出现 |
| 失败与恢复 | 可重试、人工添加/删除/调整词条；带位置模式下须重新校验位置；不把供应商分数改名为准确率 |
| AC07 | 词条数与出现次数分开展示；无定位词条不产生虚构区间；同词多次出现可逐处核对，所有统计遵守确认的关键词定义 |

### F08 词性层（POS）

| 项目 | 要求 |
|---|---|
| 输入、动作 | 对确定修订执行词性标注；若依赖分词，绑定指定分词版本并显示对应关系，已确认 POS 绑定分词结果，单选 POS 时显式补分词依赖 |

## 7. 跨功能验收场景

公开文档/验证仅用原创合成句子，例如“周宁在青禾图书馆整理笔记。周宁随后去听讲座🙂。”；人名/机构等是否属于最终标签以 TBD[D07] 为准，这个句子不是标准答案或数据集摘录。数值质量验收必须另建金标准。

| 场景 | 执行与判断 | 关联条件 |
|---|---|---|
| E01 单篇闭环 | 输入混合字符→保存重读→四类标注→保存组合→人工修改→再保存/重读→统计→导出；文本、修订、所选结果和统计语义一致，任一不符即失败 | AC01–AC14 |
| E02 重复来源 | 原创三列 CSV 含重复单元格、重复整行及引号内换行；逐单元格核对逻辑记录/列坐标，重复来源不丢，物理行和记录序号不混用 | AC03、AC15 |
| E03 文本变更 | 对已有人工结果改正文，检查旧标注仅属于旧修订；处理中旧任务回传也不能覆盖新修订 | AC04、AC05、AC12 |
| E04 四类与异常 | 分别/组合调用四类任务，包含合法空结果、工具不可用、非法标签/区间；逐层状态正确，异常不可冒充成功 | AC05–AC10 |
| E05 校对与冲突 | 从空层开始人工标注，修改/删除并保存；另一页签更新后尝试旧基线保存，应提示冲突并保留数据；重新推理不覆盖人工版 | AC11、AC12 |
| E06 同版统计和导出 | 草稿变化不改正式面板；保存/显式选版后面板更新；导出生成期间另存新修订，本次文件仍指向原清单 | AC13、AC14 |
| E07 批量恢复 | 混合成功、合法空、一层失败和全失败；中断后重读，再重试失败层，计数对账且成功历史不丢 | AC15 |
| E08 管理与可访问性 | 空列表、加载失败、窄屏和键盘完成主流程；归档/恢复按最终策略检查引用，原始附件不受影响 | AC01、AC10、AC16，第 3 节 |

这些是未来业务验证计划，不是本阶段的执行记录。依赖的标签/区间/规模阈值未冻结时，相关测试记为待确认，不用假定标签或默认端点写“已通过”。
